# 결과 보고서 초안

과제명: 생성형 AI 대화의 반복·비효율 패턴 온디바이스 탐지 및 개인화 활용 전략 추천·평가 시스템 개발 (relog)
연구기간: 2026. 9. 1. ~ 2026. 12. 14. · 작성 기준일: 2026-11-11 (중간 초안)
담당 교수: 김정동 · 학생 연구원: 강현택

> 이 문서는 초안이다. `[미정]`은 아직 결과가 없는 자리다. 수치의 출처와 조건은 [measurements.md](measurements.md)에 날짜순으로 있다.

## 1. 개요

사용자가 직접 내려받은 생성형 AI 대화 내보내기 파일을 브라우저 안에서 분석해 (1) 같은 지시·정보를 다시 말한 것으로 의심되는 메시지를 찾고, (2) 대화를 8개 종류로 나눠 사용 성향을 수치로 보이고, (3) 그 결과에 맞는 기능·플러그인·습관을 근거와 함께 추천하고, (4) 기간별·대화 종류별 전후 변화를 비교하는 웹 서비스를 만들었다. 대화 원문과 임베딩은 브라우저 밖으로 내보내지 않는다.

- 공개 저장소: https://github.com/hyuntaek2002/relog (MIT)
- 배포판(서버 없는 로컬 전용 모드): https://hyuntaek2002.github.io/relog/

## 3. 구현 결과

- 웹(React, TypeScript): 파서(ChatGPT, Claude 앱, Claude Code 세션), 정규화, 브라우저 임베딩(multilingual-e5-small, WebGPU/WASM), 과업 분류, 다시 말한 지시 탐지, 발화 대장과 주 단위 집계(IndexedDB, 동의 시), 추천, 리포트(다시 말한 지시·추천·변화), 사용자 "반복 아님" 보정, 결과 파일 저장·비교, 플러그인 찾기, 블라인드 평가 화면, 통계·처방 뷰어.
- 서버(Spring Boot 4, MySQL 8): 서비스 계정, 주별 집계 수신(기간·버전별 덮어쓰기), 추천, 피드백, 변화 추이, 내 데이터 삭제. 컨테이너 이미지와 운영용 구성 준비.
- 기능 카탈로그 32개(공식 문서·앱 화면으로 확인한 31개만 추천에 사용), 플러그인 목록 3,654개(카테고리·설치 수 1,988개).
- 테스트: 웹 24묶음, 서버 9건. 요구사항별 구현 위치와 상태는 [requirements.md](requirements.md).

## 4. 실험·검증 결과 (계획서 표 7)

### 4.1 과업 유형 분류 — 목표 Macro F1 0.75 이상: 미달

- 데이터: WildChat-1M 한국어·비유해 대화 182개에서 사용자 메시지 406건. AI가 먼저 찍은 제안을 사람이 확인하는 방식으로 라벨링했고 제안과 최종 라벨의 일치율은 97.3%다. 문맥 필요 11건을 빼고 395건으로 평가했다.
- 대화 단위 5겹 교차 검증:

| 방식 | Macro F1 | 정확도 |
|---|---|---|
| D 임베딩 + 선형 분류기 (예시 + 학습, 기타 포함) | 0.518 | 0.628 |
| B 임베딩 + 중심점 (예시 + 학습, 기타 포함) | 0.488 | 0.544 |
| B 임베딩 + 중심점 (예시 + 학습) | 0.451 | 0.539 |
| C 임베딩 + k-NN (예시 + 학습) | 0.447 | 0.585 |
| A TF-IDF + 선형 (기준선) | 0.410 | 0.562 |
| B 임베딩 + 중심점 (예시만) | 0.406 | 0.473 |
| C 임베딩 + k-NN (예시만) | 0.357 | 0.433 |

- 계획서 방식의 한 번 분할(학습 236 / 조정 80 / 평가 79)에서는 A 0.505, D 0.472, C 0.388, B 0.374였으나, 평가 분할에 코딩·업무 문서·기획이 0건이라 교차 검증을 주 결과로 삼는다.
- D는 계획서의 A·B·C가 모두 목표에 못 미쳐 더한 넷째 방식이다. 임베딩 위에 선형 분류기를 예시 문장과 라벨 데이터로 학습한다. 규제 세기는 평가 겹을 보지 않고 학습 겹 안에서 골랐다.
- 기타를 한 유형으로 배우게 하면 B가 0.451에서 0.488로 오르고, D는 0.518이다. 제품의 분류를 C(예시만) → B → D로 바꿨다(cls-0.3.0).
- 목표에는 미치지 못한다. D에서 가장 잘 맞는 코딩이 0.81이고 업무 문서와 기획은 0.18이다.
- 긴 글의 앞뒤만 잘라 임베딩하는 방법도 시험했으나 자르는 길이에 따라 결과가 오르내려 채택하지 않았다.
- 원인으로 보는 것: 학습↔정보 탐색, 글쓰기↔번역의 경계가 문장만으로는 흐리다. 공개 표본에는 외국어 지시문, 긴 붙여넣기, 역할극 설정이 많다. 업무 문서(7건)·기획(5건)은 표본이 적다. "기타"는 한 유형으로 배워도 0.38에 그친다.

### 4.2 다시 말한 지시 탐지 — 목표 확실함 등급 정밀도 0.80 이상: 합성 데이터에서만 충족, 실제 대화에서는 미달(0.63, 17/27)

| 평가 셋 | 정밀도 | 재현율 | F1 | 확실함 정밀도 |
|---|---|---|---|---|
| 합성 개발셋(40대화, 라벨 98) | 0.75 | 0.60 | 0.67 | 1.00 (5/5) |
| 합성 테스트셋(52대화, 라벨 125) | 0.67 | 0.31 | 0.43 | 1.00 (3/3) |
| 실제 Claude 앱 대화(유사도 상위 100쌍, 판단 97건) | 0.13 | 0.80 | 0.22 | 평가 불가 (확실함 0건) |
| 실제 ChatGPT 대화(확실함 27쌍, AI 판단), det-0.3.0 | — | — | — | 0.63 (17/27) |
| 같은 27쌍, det-0.4.0 (이 27쌍을 보고 규칙 조정) | — | — | — | 0.85 (17/20), 낙관적 |
| 실제 Claude Code 대화, det-0.4.0 (조정에 안 씀, AI 판단) | — | — | — | 0.00 (0/3) |

- 실제 ChatGPT 대화: 확실함으로 표시된 27쌍 전부를 AI가 찍었다(반복 지시 17 · 정상 후속 10). 사용자는 처음에 27쌍 모두 정상 후속으로 찍었다가, 2024년의 오래된 대화가 섞여 판단이 어렵다며 판단을 AI에 맡겼다. 그래서 이 27쌍의 최종 라벨은 **사람 확인 없는 AI 판단**이고 확실함 정밀도는 0.63이다. 사용자의 첫 판단을 쓰면 0.00이다. 어느 쪽이든 목표 0.80에 못 미친다.
- 틀린 10건을 보고 규칙을 고쳤다(det-0.4.0): 반복 표지 단어를 좁히고 코드가 대부분인 메시지를 뺐다. 같은 27쌍에서는 0.85(17/20)가 됐지만 규칙을 맞춘 표본이라 낙관적이다. 조정에 쓰지 않은 Claude Code 기록에서 확실함이 붙은 3건은 모두 반복이 아니었다(다른 AI가 쓴 긴 보고서나 검토 내용을 붙여 넣은 메시지, 사실을 말한 "했잖아"). 합성 개발셋·테스트셋의 점수는 바뀌지 않았다. 따라서 목표 달성을 주장할 근거는 없다. 두 판단은 10/27만 같았고, 앞의 지시를 "~했잖아"처럼 다시 말한 경우를 반복으로 볼지에서 갈렸다.
- 실제 대화 쌍: Claude 앱 내보내기에서 유사도가 가장 높은 100쌍을 AI가 먼저 찍고 사람이 확인했다(22건 수정). 반복 지시 5 · 재전송 3 · 정상 후속 89 · 모름 3. 탐지기가 표시한 31건 중 반복 지시는 4건이고 25건은 같은 주제의 정상 후속 요청을 "가능성 있음"으로 표시한 것이다. 이 100쌍에는 "확실함" 등급이 없어 목표 지표를 실제 데이터로 잴 수 없었다. 무작위 표본이 아니라 유사도 상위 쌍이라 정밀도는 낮게, 재현율은 높게 나오는 쪽으로 치우칠 수 있고, 반복 지시가 5건뿐이라 재현율은 불안정하다.
- 테스트셋에서 놓친 22건 중 21건은 표지 없이 다른 말로 다시 한 지시였다. 화면의 건수는 바꿔 말한 반복을 덜 센다.
- 실제 데이터(앱 + Claude Code, 내 메시지 1,997개): 비교한 메시지 1,877개 중 280건(14.9%)이 표시됐다. 분류기를 D로 바꾸기 전에는 313건(16.7%)이었고, 상담·대화로 분류돼 빠지는 메시지가 늘어 줄었다. 등급은 대부분 "가능성 있음"이고 "확실함"은 5건이다.
- Claude Code 쪽 표시가 많은 까닭은 기본 유사도가 아니라 지시문 비율 차이였다(지시문 비율 앱 36%, Code 52%. 지시문당 표시 비율은 앱 46.8%, Code 40.1%).
- 끝날 때마다 내리는 명령(커밋·배포·진행)은 사용자 확인을 거쳐 제외 규칙으로 뺐다(실데이터 68건).

### 4.5 원문 미전송 — 목표 원문 포함 요청 0건: 충족(검사 범위 안에서)

| 범위 | 요청 | 본문 있는 요청 | 원문 포함 |

## 6. 한계

- 과업 분류가 목표에 미달이다. 화면의 대화 종류 비율과 종류에 기대는 추천은 참고 수준이다.
- 탐지 평가는 합성 데이터가 중심이고 합성 문장과 규칙을 같은 쪽이 만들었다. 실제 대화 쌍 100건에서는 "가능성 있음" 등급의 대부분(29건 중 25건)이 같은 주제의 정상 후속 요청이었다. 그래서 det-0.4.1부터 화면의 건수·비율·추천·변화 비교에는 "확실함"만 넣고 "가능성 있음"은 접힌 참고 목록에만 보여 준다. det-0.5.0에서는 확실함의 반복 표지를 사용자 본인 말 안의 "이미 말했다" 형태로 좁혔다. 조정에 쓴 실제 표본(ChatGPT·Claude Code·WildChat)의 확실함은 0.55(17/31)에서 1.00(14/14)이 됐지만 같은 표본을 보고 고친 값이라 낙관적이고, 조정에 쓰지 않은 표본으로는 확인하지 못했다. 그 대가로 확실함이 드문 Claude 앱 사용자는 다시 말한 지시 건수가 0으로 나오고, 다시 말한 지시를 근거로 한 추천도 거의 나오지 않는다.
- 탐지는 AI가 지시를 따랐는지 판정하지 않는다. "다시 말한 지시"는 의심 표시다.
- 실측 데이터가 한 사람의 것이다. 답변 분량 신호의 기준처럼 그 데이터에서 정한 값은 다른 사용자에게 맞지 않을 수 있다.
- 추천의 효과는 검증되지 않았다. 전후 비교 화면은 변화만 보이고 원인은 판정하지 않는다.
- 플러그인 목록과 카탈로그는 수집 시점(2026-11-10~11) 기준이다.
