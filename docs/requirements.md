# 요구사항 정의서

과제: 생성형 AI 대화의 반복·비효율 패턴 온디바이스 탐지 및 개인화 활용 전략 추천·평가 시스템 (relog)
기준 문서: 2026학년도 2학기 기업연계 프로젝트 연구 계획서(2026-10-19)
최종 갱신: 2026-11-11

## 1. 목적과 대상

- 사용자가 내려받은 생성형 AI 대화 내보내기 파일을 브라우저 안에서 분석해, 같은 지시·정보를 다시 입력한 것으로 의심되는 메시지를 찾고(탐지), 어떤 일에 AI를 쓰는지 수치화하고(진단), 그 결과에 맞는 기능과 활용 방법을 근거와 함께 제시하고(처방), 적용 전후 변화를 비교한다(평가).
- 대상 사용자: 생성형 AI 유료·무료 이용자 개인. 1차 대상 플랫폼은 ChatGPT 내보내기이며 플랫폼별 어댑터 구조로 확장한다.
- 전제: 대화 원문과 임베딩은 사용자의 브라우저 밖으로 내보내지 않는다. 서버를 쓰는 경우에도 주 단위 집계 숫자와 서비스 계정, 피드백만 다룬다.

## 2. 용어

| 용어 | 뜻 |
|---|---|
| 다시 말한 지시(반복 지시 의심) | 같은 대화에서 앞서 한 지시·정보를 다시 말한 것으로 의심되는 사용자 메시지. AI가 지시를 따랐는지는 판정하지 않는다. |
| 다시 친 분량(재입력 토큰 추정치) | 다시 말한 지시로 표시된 메시지의 토큰 근사치 합. 상대 비교용. |
| 비교한 내 메시지(판단 가능 발화) | 사용자 메시지가 2개 이상인 대화의 분석 대상 메시지. 반복 비율의 분모. |
| 대화 종류(과업 유형) | 코딩, 글쓰기·교정, 학습·설명, 업무 문서, 정보 탐색, 아이디어·기획, 번역, 상담·대화 8종 + 기타 + 문맥 필요. |
| 집계 스냅샷 | 메시지 생성일 기준 주 단위 숫자 묶음. 원문 없음. |

## 5. 범위

- 본 과제 범위: ChatGPT 내보내기 분석, 내보내기 파일 분석 방식, 사전 학습 임베딩 + 기준선 비교, 다시 말한 지시 탐지·등급화, 규칙 기반 처방과 수동 카탈로그, 기간별·대화 종류별 전후 비교, MySQL 단일, Spring Boot 단일 서버, 통계·처방 최소 뷰어.
- 후속 확장(범위 밖): 브라우저 확장 실시간 수집, 분류기 파인튜닝, 모델 응답의 지시 이행 판정, 카탈로그 자동 수집, 장기 추적, DB 이중화, 서비스 분리, 스토어 정식 출시, 규칙 위반 감지와 재주입.
- 범위 밖이지만 미리 한 것: Claude 앱·Claude Code 어댑터, 대화 종류별 플러그인 추천, 플러그인 찾기.

## 7. 제약

- 학습이 필요한 모델은 쓰지 않는다. 공개된 사전 학습 임베딩과 규칙으로 1차 버전을 만든다.
- 공개 데이터셋은 라이선스 범위 안에서만 쓴다. WildChat-1M(ODC-BY)은 표본을 저장소에 넣지 않고 식별자와 라벨만 둔다. LMSYS-Chat-1M은 접근 동의와 재배포 제한이 있어 원본을 재배포하지 않는다.
- 평가 참여자에게는 수집 항목과 미수집 항목을 서면으로 알리고 동의를 받는다(docs/consent-form.md).
